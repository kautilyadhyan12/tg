# 2026-10-14 · the package folders' names cut to 30 characters (feature folder 2; branch `store-names-30`)

- **Why:** feature folder 2's first phone build (`corepack pnpm --filter mobile phone`) failed twice at `:react-native-screens:buildCMakeDebug[arm64-v8a]` with *"ninja: error: manifest 'build.ninja' still dirty after 100 tries"*. Kd: *"yes"* (`rulings/2026-10-14-store-names-30.md`). Not a ROADMAP job.
- **The cause, measured:** before it rebuilds anything, ninja 1.10.2 (Android SDK CMake 3.22.1) checks each file the build file depends on by asking Windows for that one file, by its build folder plus its relative path. It finds one at 259 characters and not at 260 or 261 (tested in a scratch folder with `-d nostatcache`, which is how that check runs). The longest such path in each C++ build folder of `ai-home-gym-b`, measured from its `build.ninja`: react-native-screens 261 (both copies; `ReactAndroidConfigVersion.cmake`), expo-modules-core 258 (both copies), the app's own 177. In `ai-home-gym` the first two are 259 and 256; in `ai-home-gym-ex1` and `-ex2` they would be 263 and 260. So ninja calls the file missing, runs CMake again, and gives up after 100 tries.
- **The change:** `.npmrc` `virtual-store-dir-max-length` 40 → 30. pnpm cuts a longer folder name in `node_modules/.pnpm` to (limit − 27) characters plus `_` and a 26-character hash (pnpm 9.15.4's `depPathToFilename`), and all four folders holding a package that builds C++ are cut to exactly 40, so each of those paths is 10 shorter: 251 and 248 here, 253 and 250 in the exercise folders.
- **Cost:** each folder rebuilds its `node_modules` once with `CI=true corepack pnpm install --frozen-lockfile` (about 12 minutes; with `CI` set pnpm does it without asking, and other commands such as tests are not affected), then builds its copy of the app once. GitHub's checks install fresh every run and are not affected.
