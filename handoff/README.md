# handoff/ — one file for each job

Since 2026-10-13 a job's handoff is a file of its own here, never an entry in
`HANDOFF.md` (the ruling of that day, `rulings/`). Two jobs' files cannot clash, so the
folder that merges second has none of the records to fix by hand.

- **Name:** `YYYY-MM-DD-<the job>.md`, the day the job began, so the folder reads in
  order: `2026-10-13-records-cannot-clash.md`, `2026-10-14-18c.md`.
- **What it holds, ten lines:** why this job · what was built · what is verified (the
  commands run) · what is open · what is next in its folder.
- **Then, as they happen,** the lines that only say what happened: round one, the
  re-check, the merge. They are not rulings and no longer go in `RULINGS.md`.
- **Last,** the job's long ROADMAP line, when ROADMAP keeps only one line of it (it used
  to go in `archive/records/ROADMAP-stories.md`).
- **To see where the last terminals stopped:** the newest files here, and `HANDOFF.md`
  for anything before 2026-10-13.
- A file belongs to its job. No other job changes it.
