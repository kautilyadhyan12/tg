# Handoff · 2026-11-09 · Stage 5 item 21a-iii-b, zod 3 to zod 4 (feature folder 1; branch `21a-iii-b-zod-4`, PR #516)

Kd's decisions: `rulings/2026-11-09-21a-iii-b.md`. The ROADMAP line as first written: *"zod 3 to zod 4 (api and shared, 247 files), and node-forge 1.4.1: what each schema accepts stays the same, stricter emails and ids checked against real ones. Sign-in before a large body is read (round one of 21a-iii-a)."*

- **Why:** GitHub's three high zod alerts (memory on oversized collections), fixed in 4.6.6; 4.6.7 taken (28 days old). Only `@expo/cli` keeps zod 3 (the phone's build tool, never on the server). **Risky** (every request's input). No migration, no new package.
- **Side by side:** every exported shared check, the old source on `zod/v3` against the new on zod 4, the same inputs (a valid sample built from each schema, then each field missing, extra or swapped for 140 odd values): 1,365 of 1,545 checks, 5,004,336 inputs, 19 kinds of difference left, all zod 4's stricter reading (ids with no uuid version, numbers past 2^53 or infinite, date-times without seconds or with `+0530`, a Date object read as an object, emoji counted as one letter). The one-off is in `packages/shared/.zod3-old/` (not in git).
- **Found and fixed:** zod 4 fills a default inside `.partial()`: a change to the weight alone would have written `metrics: {}` and wiped a person's other measurements. The patch now declares metrics without its default (tested).
- **Worst thing, first test:** a real address that signs in today still signs in (`packages/shared/test/zod4.test.ts`, 74): everyday providers in the US, Canada and India and Wikipedia's valid and invalid examples, each read by zod 3's own rule too. Breaks: no trim (2 red), the check before the trim (2 red), zod 4's html5 rule (6+ red); put back. Every id the app makes passes (gen_random_uuid, migrated uuidv5, the phone's goal id, 2,000 of them in `goalsWords.test.ts`).
- **Rewrites:** `z.string().uuid()` and the like to `z.uuid()`, `z.iso.datetime()`, `z.email()`, `z.url()`; a trim before an email check kept by `.pipe(z.email())`; `.passthrough()` to `.loose()`; `z.record` given its key; `SafeParseReturnType` to `ZodSafeParseResult`. Test ids given a uuid version (35 files). Refusals' codes are zod 4's (`invalid_value`, `invalid_format`); no screen reads them.
- **Laptop lint misses this:** the remembered lint passed files it had read under zod 3; GitHub's lint from zero found 186 more in the api and 1 in the phone app.
