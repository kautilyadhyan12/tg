## The next three jobs, as their briefs decide them (the briefs are in feature folder 2's `reviews/`, not in git)

- **37i, the phone feels whether it is moving** (`run-still-2-motion-sensor-brief.md`; ordinary). A native module `RunMotion` (shaped like `modules/heart-rate`): Android's accelerometer at 25 a second on its own thread, handing over each second's standard deviation of the acceleration's size (`{ at, sd, n }`, under 10 samples not given). Kept with the run as `LiveRun.motion` in `run-now-motion-N.json`, also while paused; never sent (a test proves the POST body is unchanged). The main work: measure `sd` on public labelled recordings (WISDM, UCI HAR, MotionSense; licences read, kept off git) and on Kd's phone with the screen locked 10 minutes; set `FEEL_STILL_BELOW` and `FEEL_MOVING_ABOVE` leaving one person out in turn (planner's guess 0.35 and 0.9 m/s²). Must hold or stop and tell Kd: four walking seconds in a row never all read still; standing in a pocket reads still 9 seconds in 10; 95 seconds in 100 have a number with the screen locked (else try the wake-up sensor, else Kd decides).
- **37j, Auto-pause and Start use the motion** (`run-still-3-auto-pause-brief.md`; ordinary, one review). In `autoPause.ts`: a point's feel is "still", "moving" or unknown. Running: 4 still points in a row (at least 3 s) pause, dated to the first; 3 still points farther than `max(10, 3 × accuracy)` from the first mean "on wheels" for the rest of the run, where every feel is unknown. Auto-paused: a still phone starts only by travelling that far (and sets on wheels, undoing the pause); a moving phone starts after 3 moving points, 10 s since the pause and `max(3, accuracy / 2)` farther from the stop (8 in a row with no usable position). With every feel unknown the rule is today's, line for line. No "Auto-paused." in the first 15 s after Go. First test: a pram at 3 and 1 m/s keeps every metre but 6.
- **37k, the line holds still with Auto-pause off** (`run-still-4-auto-pause-off-brief.md`; risky). The same rule opens and closes `LiveRun.still` stretches instead of pausing; `runSums` takes them as one more argument (`RUN_CALC_VERSION` 4, version 3's numbers with none); `saveRunRequestSchema` gains optional `still`, honoured only where the run's points stay within `travelMetres` of its first; the server goes live before the store build that sends it.
