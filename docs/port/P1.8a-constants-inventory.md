# P1.8a — Constant-Preservation Table (Part 2 §8.1)

**Status: APPROVED by Kd 2026-07-09** (reviewed against the Python source).
This is the binding input for **P1.8b** — the squat/jump/chair definitions are
authored from *these frozen values only*. Re-deriving or "improving" any
constant in P1.8b is forbidden (CLAUDE.md Part I §7(d), R5.4, T4).

**Scope:** every numeric threshold in
[`backend-ml/app/ai/pose/form_analyzer.py`](../../backend-ml/app/ai/pose/form_analyzer.py)
and [`backend-ml/app/ai/pose/rep_counter.py`](../../backend-ml/app/ai/pose/rep_counter.py).

**Column key** — *Units:* `°` = interior joint angle (180 = straight),
`hw` = hip-widths (dimensionless valgus delta), `elev` = torso-height-normalized
elevation fraction, `pts` = 0–100 score points, `fr` = frames, `s`/`ms` = time.
**`§4 field`** cites the §4 definition schema field; a `✓` marks a value the squat
worked example ([squat.v5.json](../../packages/engine/test/definitions/squat.v5.json))
already lands. **`⚙engine`** = engine-global constant (not a definition field);
those already landed in P1.4–P1.6, source cited.

## Footnotes (flagged in the P1.8a brief)

### FOOTNOTE 1 — bilateral gate: `<` vs `≤ 150°`
Legacy value is `_bilateral_engage_angle = 150` (rep_counter.py:142), but the
comparison is **strict `<`** (`other_smoothed < self._bilateral_engage_angle`,
rep_counter.py:198). Spec prose (§3.6/§8.1) writes "≤ 150°". The port kept `<`
(fsm.ts:122); DECISIONS.md (2026-07-08) records parity wins. Table records the
value 150° with operator `<` (strict). P1.8b keeps `bilateralGate: 150`; the engine
applies the strict compare. Comparison-operator note, not a value change.

### FOOTNOTE 2 — squat metric: `knee_avg` (form) vs `left_knee` (counting)
Two different joints for two different jobs in legacy:
- **Rep COUNTING** uses `left_knee`, right-knee fallback when left missing
  (rep_counter.py:15, fallback :162–164).
- **FORM scoring / depth** uses the **mean of both visible knees** = `knee_avg`
  (`_analyze_squat`, form_analyzer.py:232).

The worked example [squat.v5.json:15](../../packages/engine/test/definitions/squat.v5.json)
authors `rep.metric: "knee_avg"` for **counting**, which does **not** match legacy
counting (`left_knee`). Whether `knee_avg` counts bit-identically to `left_knee` on
the 9 goldens is **P1.8b's explicit deliverable** (DECISIONS.md Pending SPEC GAP).
The compiler wires the legacy `left_knee → right_knee` fallback only when
`metric === "knee_L"` (compile.ts:84–86); shipping `knee_avg` does not exercise that
path (the mean already absorbs a single missing knee). This is the crux P1.8b resolves.

## Flags surfaced during the audit (recorded decisions, not silent drops)

1. **`SQUAT_LOCKOUT_KNEE_MAX = 178` is dead** (form_analyzer.py:67) — defined and
   documented ("hyperextension risk") but referenced by **no check** in any analyzer
   (only comments at :35, :67). No lockout fault exists. Per R0.2, P1.8b will **not**
   invent a lockout fault; the squat definition preserves only what the code computes.
2. **Jump-squat valgus diverges from squat/chair** (form_analyzer.py:497–504):
   severe threshold is **−0.25** (not −0.30) and the score is an inline
   `100 + worst·200`, **not** the shared `_score_valgus`. The jump definition's valgus
   fault+curve are authored from these jump-local values, not copied from squat.
3. **Jump/chair have no worked example yet** — only squat has squat.v5.json. Every
   jump/chair "Lands in (P1.8b)" cell is authoring work: values above are frozen, field
   placement is P1.8b's to draft and Kd's to approve.
4. **`maxRepMs`** has no legacy source (rep_counter has no upper interval).
   squat.v5.json:20 carries `maxRepMs: 12000`, but DECISIONS.md (2026-07-08) records it
   has **no counting effect** (plausibility only). Not a ported constant.
